# SameGame 파일럿 v3 · 목표 개수만큼 글자 남기기

한 문제는 같은 입력을 사용하는 5라운드다. 매 라운드는 원래 입력에서 다시 시작한다. 참가자는 그 라운드의 삭제 방식, 우선 글자, 목표를 확인하고 **삭제할 글자를 차례대로 이어 쓴 문자열**을 제출한다.

## 한 번의 삭제

같은 글자가 2개 이상 연속되면 삭제할 수 있다. 글자를 선택하면 왼쪽부터 그 글자의 **첫 번째 삭제 가능한 묶음**에 현재 라운드의 방식을 적용한다.

| 삭제 방식 | 동작 | `AAABB`에서 `A`를 선택한 결과 |
|---|---|---|
| `whole` | 묶음 전체를 지운다. | `BB` |
| `pair` | 묶음에서 2개만 지운다. 나머지 글자는 남는다. | `ABB` |

우선 글자에 삭제 가능한 묶음이 있으면 반드시 그 글자를 선택한다. 없으면 삭제 가능한 글자 중 하나를 고른다. 삭제 후 같은 구간에서 맞닿은 글자는 합쳐진다. 입력의 ASCII 공백 한 칸은 영구 경계여서 양쪽 글자가 하나의 묶음을 이루지 않는다.

예를 들어 입력 `ABAAACCAAA`에서 목표가 서로 다른 2개, 우선 글자가 A이면, `whole`에서는 `AAC`를 제출해 `AB`를 남길 수 있다. `pair`로 바꾸면 같은 `AAC`를 적용했을 때 `ABAA`가 남는다. 마지막에 A를 한 번 더 선택한 `AACA`가 새 규칙의 정답이다.

## 종료 조건

공백을 제외하고 남은 글자 수가 목표에 처음 도달하면 멈춘다. **목표가 2이면 남은 두 글자가 서로 달라야 한다.** 같은 두 글자가 남으면 그 시점에서 실패한다.

| 목표 | 성공하는 상태 | 확인할 점 |
|---|---|---|
| 0 | 빈 문자열 또는 공백만 남은 상태 | 공백은 글자 수에 포함하지 않는다. |
| 1 | `A` | 어느 글자든 한 개면 된다. |
| 2 | `AB`, `A B`, `BA` | `AA`, `A A`, `DD`는 같은 글자 두 개이므로 실패한다. |
| 3 | `AB A` | 세 글자의 종류와 순서는 자유다. |

예를 들어 `whole`, 우선 글자 `B`, 목표 0에서 입력 `AABBAA`의 정답은 `BA`다. `B` 삭제 후 `AAAA`를 한 번에 지울 수 있다. 입력이 `AABB AA`이면 `B` 삭제 후 `AA AA`가 되어 정답은 `BAA`다. 이 경우 제출할 **행동**은 `BAA`이고, **최종 상태**에는 공백 한 칸이 남는다.

## 라운드 전환

`t`는 문제의 기본 목표, `u = (t + 1) % 4`는 다음 목표다. 예를 들어 `t = 3`이면 `u = 0`이다. `P`와 `Q`는 서로 다른 우선 글자다.

| 순방향 라운드 | 삭제 방식 | 목표 | 우선 글자 | 직전 라운드에서 바뀐 항목 |
|---|---|---:|---|---|
| R1 | `whole` | t | P | 시작 |
| R2 | `pair` | t | P | 삭제 규칙 (`rule`) |
| R3 | `pair` | t | Q | 우선 조건 (`condition`) |
| R4 | `whole` | t | Q | 삭제 규칙 (`rule`) |
| R5 | `whole` | u | Q | 목표 (`goal`) |

역방향 문제는 위 표를 아래에서 위로 진행한다. 어느 방향이든 전환마다 한 항목만 바뀐다. 50문제의 전환 200회 중 삭제 규칙 전환은 100회, 우선 조건 전환과 목표 전환은 각각 50회다.

## 파일과 채점

- `problems.json`은 공개 입력과 각 문제의 `round_settings`를 담는다. A–E 글자 수는 입력당 28~32개다. 총 50문제(250라운드) 중 공백 없는 입력은 30개, 공백 한 칸이 있는 입력은 20개다. 기본 목표 0·1·2·3인 문제는 각각 13·13·12·12개다.
- `answer_key.json`의 `rounds`에는 라운드별 해답 예시가, `transitions`의 `kind`에는 전환 유형이 있다. 제출한 삭제 순서는 해당 라운드 설정으로 직접 재생해 채점한다. 직전 설정에서는 성공하고 현재 설정에서는 실패하는 제출이 `previous_only`다.
- `rule` 전환에서 같은 문자 입력으로 길이 3 이상의 묶음을 선택하면 `whole`과 `pair`의 다음 상태가 달라진다. 이 위치는 규칙 차이가 드러나는 기회다. 참가자가 해당 글자를 입력했다는 사실만으로 어느 방식을 적용했다고 판단할 수는 없다. 이 파일럿에서는 `whole` 정답의 최대 행동 수가 `pair` 정답의 고정 행동 수보다 작아, 두 방식의 정답 행동열 집합이 겹치지 않는다.

이 디렉터리에서 전체 데이터를 검증하거나 개별 제출을 채점한다. 아래 두 번째 명령은 실제 3개 남기기 정답으로 최종 상태 `"AB A"`를 만든다. 마지막 명령은 2개 남기기에서 `BB`가 남아 실패하는 경우다.

```sh
python3 validate_pilot.py
python3 validate_pilot.py --grade SG-036 2 EEDCBCABDAD
python3 validate_pilot.py --grade SG-003 4 BDCEEDACAC
```

고정 시드로 데이터와 채점 키를 다시 만들려면 `node generate_pilot.mjs`를 실행한다.
