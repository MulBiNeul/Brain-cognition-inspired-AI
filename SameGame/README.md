# SameGame 파일럿 v5 · 글자 묶음을 지워 목표 개수 남기기

50문제 × 5라운드에서 **서로 다른 입력 문자열 250개**를 사용한다. 각 입력은 A–E로 된 글자 28~32개를 담는다. 목표는 남길 글자 수 0·1·2·3 중 하나다. 한 문제에서 네 목표를 모두 사용하며 이웃한 두 라운드의 목표는 다르다.

## 푸는 법

- 매번 삭제 가능한 글자 중 하나를 자유롭게 고른다. 그 글자가 **2개 이상 연속된 가장 왼쪽 묶음 전체**를 지운다. 삭제 후 같은 구간에서 서로 맞닿은 글자는 합쳐진다.
- 공백을 제외한 글자 수가 목표에 처음 도달하면 즉시 멈춘다. **목표가 2일 때는 서로 다른 두 글자**가 남아야 한다. `AB`, `A B`, `BA`는 성공하고 `AA`, `A A`는 실패한다. 목표가 3이면 글자 종류와 순서는 자유이므로 `AB A`도 성공이다.
- 응답으로는 **삭제한 글자를 순서대로 이어 쓴 행동열**을 제출한다. 채점기는 그 라운드의 입력에서 행동열을 재생해 삭제 가능 여부와 목표 도달 시점을 확인한다.

## 모든 정답에 필요한 병합

원래 입력에서 떨어져 있던 같은 글자들이 다른 묶음을 지운 뒤 하나로 붙을 수 있다. **서로 다른 원래 묶음에서 온 글자들이 합쳐진 묶음을 지운 행동**을 병합 삭제 1회로 센다. 각 라운드의 모든 유효한 정답에는 이런 삭제가 적어도 **두 번** 필요하다. 그중 적어도 한 번은 **구성 글자가 전부 처음에 한 개씩 떨어져 있던 묶음**을 지워야 한다.

짧은 예로 `ABCCBA`를 0개로 줄이는 정답은 `CBA`다.

| 행동 | 삭제 후 | 지운 묶음이 만들어진 과정 |
|---|---|---|
| C | `ABBA` | `CC`는 처음부터 붙어 있었다. |
| B | `AA` | 처음에 떨어져 있던 두 B가 C 삭제 뒤 붙었다. |
| A | 빈 문자열 | 처음에 떨어져 있던 두 A가 B 삭제 뒤 붙었다. |

이 예에서는 B와 A 삭제가 병합 삭제이고, 두 묶음 모두 원래 한 개씩이던 글자로만 구성된다.

실제 문항 SG-001의 2라운드는 1글자 남기기다. 대표 정답의 마지막 세 행동은 `ADAADAE` → (A 삭제) `ADDAE` → (D 삭제) `AAE` → (A 삭제) `E`다. 13·14번째에 지운 `DD`와 `AA`는 모두 원래 입력에서 각 글자가 단독으로 있던 묶음이다.

## 공백의 역할

50문제 중 30문제는 다섯 입력 모두 공백이 없고, 20문제는 매 입력에 ASCII 공백 한 칸이 있다. 이 공백은 **영구 경계**다. 공백 양쪽 글자는 합쳐지지 않으며, 공백만 남은 상태는 목표 0을 충족한다. 문항별 공백 유무와 목표 순서는 직전 파일럿의 배정을 유지한다.

예를 들어 목표가 서로 다른 2글자일 때 `CBAABBAA`는 `BA`로 `CB`를 남긴다. 입력을 `CBAABB AA`로 바꾸면 B를 지운 뒤 `CBAA AA`가 된다. A 묶음 두 개를 차례로 지워야 하므로 정답은 `BAA`다. 공백이 있는 **100개 라운드 모두**에서 대표 정답을 공백만 없앤 입력에 그대로 재생하면 실패한다. 채점 키에는 공백이 있는 문항마다 비교 사례 하나(`space_probe`)가 있다.

## 파일과 실행

- `problems.json`의 `round_settings`에서 각 라운드의 입력과 목표를 읽는다. [ROUND_SCHEDULE.md](ROUND_SCHEDULE.md)에서 현재 250개 라운드를 확인할 수 있다.
- `answer_key.json`은 대표 정답과 **모든 정답에서 각각 구한 최소 횟수**를 담는다. 250라운드에서 병합 삭제 최소 횟수(`min_merged_deletions`)는 4~12회, 그중 원래 한 개씩이던 글자로만 구성된 묶음의 삭제 최소 횟수(`min_singleton_merge_deletions`)는 2~12회다.
- 이 디렉터리에서 `python3 validate_pilot.py`로 데이터 전체를 검증한다. 개별 제출은 `python3 validate_pilot.py --grade ID ROUND ACTIONS`로 채점한다. `ROUND`는 1~5, `ACTIONS`는 삭제 행동열이다. 같은 CLI로 v2–v4 데이터도 검증·채점할 수 있다.

v5는 입력 구조와 기본 삭제 수행을 검증하는 파일럿이다. 추가 실험 규칙은 후속 단계에서 정하며, v5 채점에서는 이전 규칙을 따른 오류를 집계하지 않는다. v3·v4의 규칙과 라운드 일정은 Git 이력에서 확인할 수 있다.
