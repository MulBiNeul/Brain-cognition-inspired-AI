# SameGame 파일럿 v4 · 목표 개수만큼 글자 남기기

같은 입력을 5라운드 동안 풀며, **남겨야 하는 글자 수가 매 라운드 바뀐다.** 매번 원래 문자열에서 시작한다. 참가자는 현재 목표, 우선 글자, 묶음 선택 방향을 확인하고 삭제할 글자를 차례대로 이어 쓴 행동열을 제출한다.

## 삭제와 종료

1. 선택한 글자가 **2개 이상 연속된 묶음 전체**를 지운다. 그런 묶음이 여러 개이면 `selection_side`가 `left`일 때 가장 왼쪽 묶음을, `right`일 때 가장 오른쪽 묶음을 지운다. 예를 들어 `ABAAACCAAA`에서 `A`를 선택하면 `left`의 결과는 `ABCCAAA`, `right`의 결과는 `ABAAACC`다. 맨 앞에 혼자 있는 `A`는 두 방향 모두 삭제 대상에서 제외된다.
2. 우선 글자의 묶음을 지울 수 있으면 그 글자를 선택해야 한다. 없으면 지울 수 있는 글자 중에서 고른다. 삭제 후 같은 구간에서 맞닿은 글자는 합쳐진다. ASCII 공백 한 칸은 영구 경계여서 양쪽 글자가 하나의 묶음을 이루지 않는다.
3. 각 삭제 후 공백을 제외한 글자 수를 센다. 목표 개수에 처음 도달한 시점에 판정하고 멈춘다. **목표가 2이면 남은 두 글자가 서로 달라야 한다.** 목표 개수를 건너뛰거나, 성공 상태에 도달한 뒤 행동을 더 제출하면 실패한다.

| 목표 글자 수 | 성공하는 상태 예시 | 판정 |
|---|---|---|
| 0 | `""`, `" "` | 공백만 남아도 성공 |
| 1 | `A` | 어느 글자든 한 개 |
| 2 | `AB`, `A B`, `BA` | 서로 다른 두 글자. `AA`, `A A`, `DD`는 실패 |
| 3 | `AB A` | 세 글자의 종류와 순서는 자유 |

선택 방향 `left`, 우선 글자 `B`, 목표 0일 때 입력 `AABBAA`의 정답은 `BA`다. `B` 삭제 후 `AAAA`가 되어 한 번에 지울 수 있다. 입력이 `AABB AA`이면 `B` 삭제 후 `AA AA`가 된다. 제출할 **행동**은 `BAA`이고, **결과**로 공백 한 칸이 남는다.

## 5라운드 구성

50문제 모두 5라운드에서 목표 0·1·2·3을 한 번 이상 사용한다. 한 목표가 두 번 등장하며, 이웃한 두 라운드는 항상 목표가 다르다. R1부터 R5까지 각 위치에서 목표별 빈도는 12~13회이고, 250라운드 전체에서는 목표별로 62~63회다.

각 문제 ID의 우선 글자 순서는 v3와 같다. 문제당 네 번의 전환 중 두 번은 목표만 바뀐다. 한 번은 우선 글자가 목표와 함께, 다른 한 번은 좌우 선택 방향이 목표와 함께 바뀐다. 전체 200회 중 **목표만 100회, 목표와 우선 글자 50회, 목표와 선택 방향 50회**다. 선택 규칙만 바뀌는 전환은 0회다. [50문제 전체의 v3·v4 라운드 설정 비교](ROUND_SCHEDULE.md)

## 채점과 전환 해석

제출한 행동열을 현재 라운드의 원래 입력에서 재생해 삭제 가능 여부, 우선 글자 준수, 종료 시점을 확인한다. 같은 라운드에 유효한 행동열이 여러 개일 수 있다.

`previous_only`는 **같은 제출이 직전 라운드의 전체 설정에서는 성공하고 현재 라운드에서는 실패**했음을 뜻한다. 목표만 바뀐 전환에서는 두 설정의 차이가 목표 하나다. 동시 전환에서는 바뀐 두 항목 가운데 하나씩만 직전 값으로 되돌려 같은 제출을 재생한다. 이를 부분 반사실 재생이라고 한다.

| 동시 전환 | 목표만 직전 값으로 재생 | 다른 변경 항목만 직전 값으로 재생 |
|---|---|---|
| 목표와 우선 글자 | 직전 목표 + 현재 우선 글자 | 현재 목표 + 직전 우선 글자 |
| 목표와 선택 방향 | 직전 목표 + 현재 방향 | 현재 목표 + 직전 방향 |

부분 재생은 제출과 양립하는 설정을 확인한다. 동시 전환에서 `previous_only` 하나만으로 참가자가 어느 항목을 기억했는지 구분할 수는 없다. 특히 `goal_and_rule` 전환에서는 직전 해답 예시를 따라가며 같은 상태에서 두 방향으로 같은 글자를 지워 보면, 다음 문자열이 실제로 달라지는 지점이 적어도 두 곳 있다. 그 위치의 글자 입력 하나만으로 참가자가 어느 방향을 적용했는지 판정할 수는 없다.

동시 전환 100개에는 각각 `transitions[].carryover_probe.answer`에 진단용 행동열이 들어 있다. 직전·현재 목표와 직전·현재 방향(또는 우선 글자)을 조합한 네 설정에 재생하면 **현재 목표 + 직전 방향(또는 직전 우선 글자)**에서만 성공한다. 이 예시는 직전 전체 설정에서도 실패하므로 `previous_only`는 거짓이다. 이를 통해 새 목표를 달성하면서 직전 선택 규칙이나 우선 조건을 따르는 제출을 구별할 수 있다. 개별 제출을 채점할 때 우선 글자 위반은 그 단계에 기록하고, 행동이 물리적으로 가능하면 재생을 계속해 반복 위치를 센다. 두 설정이 함께 바뀐 100개 전환에서는 직전 대표 정답과 진단용 행동열을 각각 현재 설정으로 재생했을 때도 우선 글자 충돌 또는 좌우 선택의 결과 차이가 적어도 두 번 드러난다. 참가자의 지속 오류율은 실제 제출로 계산한다.

예를 들어 SG-001의 R5 목표는 서로 다른 두 글자이고, 우선 글자는 E다. R4의 오른쪽 선택 방식으로 `EEAAADDDBCB`를 실행하면 `CA`가 남는다. R5의 왼쪽 방식에서 같은 행동열을 제출하면 `A` 한 글자만 남는다. 현재 경로의 1·3·4·6·7·9번째 행동에서 왼쪽과 오른쪽을 선택한 다음 상태가 다르다. R5의 유효한 제출 예시는 `EEAADCBADDB`이고 최종 상태는 `CA`다.

## 파일과 실행

- `problems.json`은 문제의 입력과 5개 라운드 설정(`round_settings`)을 담는다. 공개 설정에는 목표, 우선 글자(`priority`), 선택 방향(`selection_side`)이 모두 들어 있다. 입력당 A–E 글자 수는 28~32개다. 50문제 중 30개에는 공백이 없고 20개에는 공백 한 칸이 있다.
- `answer_key.json`의 `rounds`에는 정답 행동열의 예가, `transitions`에는 인접 라운드의 전환 정보가 들어 있다.
- 이 디렉터리에서 `python3 validate_pilot.py`로 전체 데이터를 검증한다. 개별 제출은 `python3 validate_pilot.py --grade ID ROUND ACTIONS`로 채점한다. `ROUND`는 1~5이고 `ACTIONS`에는 실제로 삭제할 글자열을 넣는다. 재생성 명령은 `node generate_pilot.mjs`다.
