# 사람 평가: HTML 실행과 JSON 저장

`Hanoi_Human_Evaluation.html` 파일 하나를 Chrome, Edge 또는 Safari에서 엽니다. 참가자에게 이 파일을 전달하면 별도 설치, Python 실행, API 키, 인터넷 연결 없이 평가할 수 있습니다. 연구자가 정한 익명 참여 코드(예: `H001`)를 입력하고 시작합니다.

## 조건

| 항목 | 설정 |
|---|---|
| 유형별 문제 수 | 기둥 이동 제한 4 / 연속 출발 제한 3 / 선행 방문 조건 3 |
| T | 모든 라운드 최대 10회 제출 |
| k | R1 포함 모든 라운드 연속 정답 2회 |
| 라운드 | 문제당 최대 5개 |
| 라운드 실패 | T 내 k를 충족하지 못하면 해당 문제의 남은 라운드 제외 |
| 계획 길이 | 1~30회 이동; 왕복 계획 허용 |
| 피드백 | 정답 / 오답 / 규칙 위반 / 정답이지만 규칙 위반 |

`configs/human.toml`과 `data/human_10.json`의 조건을 HTML에 포함합니다. HTML은 생성 시점의 설정을 사용합니다. T, k, 문제를 바꿀 때는 아래 명령으로 파일을 다시 생성하고 새 평가를 시작합니다.

```bash
python3 build_human.py
```

참가자 화면에는 추가 이동 제한, 목표 기둥, 유형 이름, 라운드 번호·전환, T, k, 지속적 오류 진단을 표시하지 않습니다. 초기 배치는 현재 제출에 필요한 정보로 보여 줍니다. 시작 기둥이 목표가 아니라는 힌트를 추가하지 않습니다.

## 조작

출발 기둥을 클릭한 뒤 도착 기둥을 클릭하면 맨 위 원반을 옮깁니다. 원반 번호와 이동 순서를 계획 목록에서 확인할 수 있습니다. 빈 기둥 선택, 같은 기둥 선택, 큰 원반을 작은 원반 위에 놓는 클릭은 이동을 추가하지 않습니다. 한 단계 취소, 계획 초기화, 이전 계획 불러오기를 지원합니다. 빈 계획은 제출할 수 없습니다.

전체 계획을 제출한 뒤에만 네 가지 피드백 중 하나를 받습니다. 추가 이동 제한이나 목표 도달 여부는 계획을 작성하는 동안 알려주지 않습니다. 한 문제 안의 이전 계획·초기 배치·피드백은 기록에서 확인할 수 있고, 문제가 바뀌면 화면의 이전 기록도 새로 시작합니다. 전체 제출 기록은 결과 JSON에 계속 보존됩니다.

`정답`만 k를 늘립니다. `정답이지만 규칙 위반`을 포함한 나머지 세 피드백은 연속 정답 횟수를 초기화합니다. 다음 제출은 해당 초기 배치에서 다시 시작합니다.

## 저장과 이어하기

- 화면 상단의 **진행 저장 · JSON** 또는 완료 화면의 **결과 저장 · JSON**을 눌러 파일을 내려받습니다. 브라우저의 다운로드 폴더 또는 사용자가 선택한 위치에 저장됩니다.
- 같은 브라우저에서는 자동 저장된 기록을 **저장된 진행 이어하기**로 불러올 수 있습니다. 브라우저 저장이 차단되거나 가득 차면 화면에 안내합니다. 이 경우 JSON을 내려받아 보관합니다.
- 다른 브라우저나 컴퓨터에서는 같은 HTML을 열고 **불러오기**에서 내려받은 JSON을 선택합니다. 서버나 원래 컴퓨터의 파일은 필요하지 않습니다.
- 중간 JSON에는 제출 기록과 진행 상태, 편집 중인 계획이 포함되므로 이어서 진행할 수 있습니다. 이미 제출된 계획은 다시 채점하여 제출 횟수를 늘리지 않습니다.
- 완료 후 결과 JSON을 연구자에게 전달합니다. 브라우저 자동 저장만으로 연구자에게 전송되지는 않습니다.

기록은 자동으로 연구자 컴퓨터의 `runs/`에 생기지 않습니다. 사용자가 내려받은 JSON이 독립형 HTML 평가의 결과 파일입니다. 여러 사람이 한 컴퓨터를 이용한다면 이전 사람의 JSON을 먼저 저장하고, 새 참여 코드를 입력해 새 평가를 시작합니다. 한 평가를 여러 탭에서 동시에 진행하지 않습니다.

## 결과와 채점

JSON에는 참여 코드, 세션 ID, 고정 실험 조건·문제, 제출별 이동과 피드백, 시간, 채점 결과, 라운드별 PER, 문제별 MPE, 유형별·전체 MPE 및 평균 오답률을 저장합니다. 비율은 0~1 값이며 백분율로 표시할 때 100을 곱합니다. 진행하지 않은 라운드는 0으로 채우지 않습니다.

지표는 [지표 정의](metrics.md)를 따릅니다. R1은 오답률에 포함하고 MPE에서 제외합니다. HTML의 JavaScript 채점 구현은 모델용 Python 채점기와 같은 채점·집계 기준을 사용합니다. 기본 이동 오류를 입력 단계에서 차단하는 사람 화면과 자유 JSON을 받는 모델은 입력 수단이 다릅니다.

제출별 시간은 계획 작성 화면이 열린 시점부터 제출까지 브라우저 시계로 측정합니다. 화면을 열어 두거나 중단한 시간도 포함하고, 피드백 화면에 머문 시간은 제외합니다. 모델 API 응답 시간과는 측정 구간이 다릅니다.

단일 HTML은 오프라인 채점을 위해 문제·목표·규칙을 내부에 포함합니다. 참가자 화면에는 표시하지 않지만 소스와 연구자용 JSON을 검사하면 볼 수 있습니다. JSON 불러오기 검사는 기록의 일관성을 확인하는 기능이며, 의도적인 파일 편집을 방지하는 보안 장치는 아닙니다.

## 파일 구성

- `Hanoi_Human_Evaluation.html`: 참가자에게 전달할 독립형 실행 파일.
- `build_human.py`: 설정·문제·화면 코드를 단일 HTML로 묶는 생성기.
- `human_web/engine.js`: 채점, 라운드 진행, 지표, 결과 JSON과 복원 검증.
- `human_web/offline.js`: 브라우저 자동 저장과 파일 다운로드·불러오기.
- `human_web/app.js`, `index.html`, `style.css`: 화면과 클릭 입력.
