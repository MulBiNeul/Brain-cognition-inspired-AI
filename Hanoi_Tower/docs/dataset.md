# 데이터셋

## 모델 평가: 3유형 × 100문제

`data/benchmark_300.json`은 300문제·1,500라운드로 구성된 고정 실험 자료입니다. 세 모델은 같은 파일을 사용하며 배열 순서와 문제 ID가 일치합니다.

| 실행 순번·문제 ID | 유형 | 문제 수 | 규칙 후보 수 |
|---|---|---:|---:|
| 1–100 · P001–P100 | `peg`: 지정한 방향의 기둥 간 이동 금지 | 100 | 12 |
| 101–200 · P101–P200 | `source_sequence`: 직전 출발 기둥에 따라 다음 출발 기둥 제한 | 100 | 12 |
| 201–300 · P201–P300 | `visit`: 지정 원판의 선행 방문 전 원판 3 이동 제한 | 100 | 8 |

기둥은 A/B/C/D, 원판은 3개입니다. `initial_positions` 배열은 원판 1, 2, 3 순서이며, 원판 1이 가장 작습니다. 기둥의 원판 목록을 표시할 때는 큰 원판부터 나열하므로 `[3, 2, 1]`의 마지막 원판 1이 맨 위입니다.

한 문제는 한 규칙 유형을 유지하면서 라운드마다 초기 상태·구체적인 이동 제한·목표 기둥을 바꿉니다. 5개 초기 배치 계열은 같은 기둥에 모두 모인 상태, 원판 두 개가 같은 기둥인 세 경우, 모두 다른 기둥에 있는 상태입니다. 각 문제에서 이 계열을 한 번씩 사용합니다.

각 유형의 전체 500라운드에서 규칙 후보별 빈도 차이는 최대 1회입니다. `peg`와 `source_sequence`의 후보는 각각 41–42회, `visit` 후보는 각각 62–63회 사용합니다. 각 문제의 5개 제한은 서로 다르고, 인접 라운드의 목표 기둥도 다릅니다.

제공된 JSON은 고정 평가 입력입니다. 메타데이터에 기록된 출처는 연구 이력이며, 실험 실행이나 검증에 별도 과거 자료·번호 대응표가 필요하지 않습니다.

## 사람 평가: 4/3/3 표본

`data/human_10.json`에는 모델 자료와 ID·내용이 동일한 10문제가 들어 있습니다.

| 유형 | 문제 ID |
|---|---|
| 기둥 이동 제한 | P017, P035, P041, P050 |
| 연속 출발 제한 | P152, P154, P160 |
| 선행 방문 조건 | P253, P286, P288 |

고정 시드로 선정한 표본이며 모델 점수나 응답을 선정에 사용하지 않았습니다. 사람 평가에서는 위 순서대로 문제 1–10을 표시하고 실제 문제 ID는 결과 JSON에 저장합니다.

## 검증

```bash
python3 validate_problems.py
python3 validate_problems.py data/human_10.json
python3 validate_problems.py --output generated/validation.json
```

기본 대상은 `data/benchmark_300.json`입니다. 지정된 JSON만 읽어 검증하며, `--output`을 지정했을 때만 보고서를 저장합니다. 검증 보고서로 현재 데이터 파일을 덮어쓸 수 없습니다.

독립적인 스택 재생과 BFS 탐색으로 다음을 확인합니다.

- 기본 하노이 이동법, 30회 이내 해결 가능성, 저장된 최단 경로.
- 현재 제한을 위반하는 기본 최단 해법의 존재.
- R2 이후 현재 초기 상태·목표에서 이전 제한을 지키고 새 제한을 위반하는 경로.
- 문제 안의 서로 다른 제한·초기 배치, 초기 배치 계열, 목표 전환.
- ID 중복과 기둥 이름을 일괄 바꾸면 같아지는 문제 중복.
- 실제 내용과 메타데이터의 문제 수·규칙 빈도 일치.

규칙 빈도 균형은 이를 선언한 전체 자료에 적용합니다. 사람용 표본에 전체 자료의 균형 조건을 강제하지 않습니다.

## 새 후보 생성

```bash
python3 generate_problems.py --types peg source_sequence visit --per-type 100 --seed 20261029 --output generated/problems.json
```

유형, 유형별 문제 수, 시드, 저장 경로를 지정할 수 있습니다. 현재 세 유형 각 100문제가 기본값이며 전체 문제 수는 최대 300개입니다. 생성기는 규칙 템플릿과 로컬 상태 공간 탐색을 사용하고, LLM API나 모델 결과를 사용하지 않습니다.

이 명령은 **새 후보**를 생성합니다. 같은 시드를 사용해도 제공된 고정 300문제를 바이트 단위로 재현하는 명령은 아닙니다. 현재 실험을 재현할 때는 저장소의 고정 JSON을 그대로 사용합니다. 생성한 후보를 사용하려면 해당 파일을 검증하고 모델 설정의 `dataset`을 명시적으로 바꿉니다.

## 구현

| 파일 | 역할 |
|---|---|
| `dataset_tools/generate.py` | 후보 구성과 저장 |
| `dataset_tools/rules.py` | 생성용 규칙 열거·상태 공간 탐색 |
| `dataset_tools/validate.py` | 데이터 구조·전환·중복·빈도 검증 |
| `hanoi/validation.py` | 생성기와 독립적인 스택 재생·최단 경로 검증 |

생성·검증에 사용하는 해법은 참가 모델에게 전달하거나 모델 응답 대신 사용하지 않습니다.
