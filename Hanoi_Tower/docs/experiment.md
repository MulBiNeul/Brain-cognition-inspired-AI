# 실험 설정

## 실행 조건

| 항목 | 값 |
|---|---|
| 설정 파일 | `configs/sol.toml`, `configs/opus.toml`, `configs/sonnet.toml` |
| 실행 자료 | `data/benchmark_300.json` |
| 모델 | GPT-6.1 Sol / Claude Opus 5.5 / Claude Sonnet 5.5, 모두 medium |
| 유형 | 기둥 이동 제한, 연속 출발 제한, 선행 방문 조건 |
| 문제 수 | 유형별 100개, 총 300개를 각 모델이 실행 |
| 보드 | 기둥 A/B/C/D, 원판 3개 |
| 라운드 | 문제당 최대 5개 |
| T / k | 모든 라운드 T=10, k=2; R1 포함 |
| 변화 | 라운드마다 초기 상태·추가 이동 제한·목표 기둥 변경 |
| 제출 | 전체 이동 계획 JSON, 1~30개 이동 명령 |
| 출력 한도 | 25,000토큰 |
| 종료 | T 내 k 미달 시 남은 라운드 미실행, 다음 문제 시작 |
| 문맥 | 같은 문제 내 대화와 원본 추론 상태 유지, 문제 전환 시 초기화 |
| 모델 도구 | 없음 |
| README 실행 명령의 결과 폴더 | `runs/sol_300/`, `runs/opus_300/`, `runs/sonnet_300/` |

T와 k는 설정 파일에서 바꿀 수 있는 하이퍼파라미터이며 정수 `1 <= k <= T`를 만족해야 합니다. `r1_apply_k = true`이면 R1에도 k를 적용하고, false이면 R1은 한 번 정답으로 통과합니다. R1의 최대 제출 수에는 항상 T를 적용합니다. 이미 시작한 실행을 재개하면 최초 실행에 저장된 조건을 사용합니다.

## 피드백과 채점

| 모델에게 전달하는 영어 | 의미 | 정답 여부 |
|---|---|---|
| Correct | 기본 이동법·추가 제한·목표를 모두 충족 | 정답 |
| Incorrect | 정답이 아니고 추가 제한 위반이 발견되지 않음 | 오답 |
| Rule violation | 추가 제한을 위반했고 목표 달성이 확인되지 않음 | 오답 |
| Correct, but rule violation | 기본 이동법상 목표 배치에 도달했지만 추가 제한 위반 | 오답 |

`Correct`만 연속 정답 횟수를 증가시키고 나머지는 0으로 초기화합니다. 각 제출은 그 라운드의 초기 상태에서 다시 시작합니다. 전체 계획을 순서대로 실행한 최종 배치를 검사하며, 중간에 목표에 도달했다고 즉시 정답으로 인정하지 않습니다.

추가 제한을 위반한 이동도 기본 하노이 이동법상 가능하면 진단을 위해 재생합니다. 첫 기본 이동 오류에서 경로 추적을 멈추고, 그 오류 이동에서 식별 가능한 추가 제한 위반까지 집계합니다. 이후 실행할 수 없는 이동을 가정하여 오류를 추가하지 않습니다. 지속적 오류는 제출당 최대 한 번입니다. 계산식은 [지표 정의](metrics.md)에 있습니다.

추가 제한의 구체적인 내용, 목표 기둥, 라운드 번호·전환, T·k, 지속적 오류 여부는 모델에게 안내하지 않습니다. 네 가지 피드백으로 규칙 위반 여부와 목표 달성 여부에 관한 정보를 제공합니다.

## 사람 평가와 안내 문구

사람 평가는 같은 세 유형을 4/3/3으로 구성한 10문제이며 T=10, k=2를 R1에도 적용합니다. `configs/human.toml`과 `data/human_10.json`을 사용합니다. 라운드 진행, 초기 배치 복원, 피드백 분류, T 소진 처리 및 PER/MPE 계산은 모델 평가와 같습니다.

모델 안내는 영어, 사람 안내는 같은 의미의 한글입니다. 사람은 기둥 클릭과 현재 배치 시각화로 계획을 작성하며 기본 이동 오류는 입력 단계에서 차단합니다. 이 입력 방식은 모델의 자유 JSON 제출과 다른 보조 수단입니다. 이전 기록은 같은 문제 안에서만 열람하고 문제 전환 시 새 기록으로 시작합니다. 자세한 내용은 [사람 평가](human.md)에 있습니다.

최소 이동 횟수는 공개 제출 조건이며 모델 안내는 다음과 같습니다.

```text
A plan must contain between 1 and 30 move commands.
Empty move lists are not valid submissions.
```

시작 기둥이 목표가 아니라는 안내는 추가하지 않습니다. 비어 있지 않은 왕복 계획도 최종 배치와 이동 제한에 따라 채점합니다. 초기 배치가 한 기둥에 모여 있어도 채점 기준은 동일합니다.

## 구성과 실행 순서

모델용 공개 자료는 세 유형 각 100문제로 구성된 고정 JSON입니다. 문제 생성에는 모델 성능을 사용하지 않습니다. 세 모델은 같은 파일을 P001~P300 순서로 실행합니다. 기둥 이동 제한 P001~P100, 연속 출발 제한 P101~P200, 선행 방문 조건 P201~P300이며 실행 순번과 ID가 일치합니다.

사람용 10문제는 고정된 4/3/3 표본이며, ID와 5개 라운드의 내용은 공개 300문제의 해당 문제와 같습니다. 사람용 자료와 공개 300문제의 해당 문제는 동일한 ID와 내용을 사용하므로 직접 비교할 수 있습니다. 사람 평가에서도 모델 결과를 선정에 사용하지 않습니다.

## 기록과 재개

실행 설정, 문제 목록, 지시문은 `protocol.json`에 고정합니다. 중단 원인에 관계없이 `.venv/bin/python run.py --resume runs/sol_300`으로 재개합니다. 완료 응답은 원본 형식으로 재사용하고, 같은 문제의 대화·추론 상태와 연속 정답 횟수를 복원합니다. 기존 코드·설정·문제가 달라졌거나 기록의 무결성 검사에 실패하면 재개를 차단합니다.

요청을 보냈지만 응답 파일이 없는 경우에는 같은 제출을 한 번 다시 요청합니다. 새 답변은 해당 제출로 한 번만 채점하며, 이전 전송의 시작·오류·부분 스트림 기록은 보존합니다. 서버에서 이전 요청을 이미 처리했을 가능성이 있어 비용은 중복될 수 있습니다. 재개 후에도 통신 오류가 나면 다시 멈추며, 실행 중 자동 재시도 루프는 없습니다. `--check-only`와 `--dry-run`은 미완료 제출을 재요청하지 않습니다.

토큰 한도·공백 반복 등 생성 실패 응답이 이미 저장된 제출은 다시 생성하지 않습니다. 해당 제출은 미채점으로 두고 그 문제의 남은 라운드를 제외한 뒤 다음 문제로 진행하는 기존 방침을 유지합니다.

Sol은 API에 `reasoning.summary="auto"`를 요청합니다. 반환된 요약을 시도별 UTF-8 텍스트와 검색용 목록으로 저장합니다. 요약이 반환되지 않으면 `not_returned`로 기록하며, 이를 추론하지 않았다는 증거로 해석하지 않습니다. 요약을 얻기 위한 추가 API 호출은 없습니다.

API가 반환한 추론 상태는 공급자의 원본 형식을 보존하여 같은 문제의 다음 호출에 전달합니다. 요약 텍스트를 별도 참가자 메시지나 피드백으로 주입하지 않습니다. 문제 전환 시 대화와 추론 상태를 새로 시작합니다.
